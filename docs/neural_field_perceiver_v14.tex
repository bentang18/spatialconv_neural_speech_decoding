%% ====================================================================
\section{Problem and Scope}
%% ====================================================================

Each patient's $\mu$ECoG array is a sparse sample of cortical high-gamma activity during non-word repetition. Arrays are placed by the surgeon, not by protocol. Channel indices therefore have no shared meaning across patients.

Phase 1 asks one concrete question:
\begin{quote}
Can a fixed-atlas, shared regional model decode the 3-phoneme sequence of each trial across patients, without learned per-patient calibration?
\end{quote}

The task is the PhonemeSequence non-word repetition dataset:
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item 52 canonical tokens, each 3 phonemes long
\item 9 phoneme classes
\item one sample = one response-onset-locked trial
\item input window: $t_{\min}=-0.5$\,s, $t_{\max}=1.0$\,s
\item signal: z-scored high-gamma at 200\,Hz
\end{itemize}

Phase-1 training and evaluation are \textbf{left hemisphere only}. Core patients are S14, S26, S33, and S62. Extended left-hemisphere patients S16, S23, and S39 audit in parallel. Right-hemisphere patients and cross-modality joins are deferred.


%% ====================================================================
\section{Design Principle}
%% ====================================================================

v14 is organized around a hard split:
\begin{enumerate}[leftmargin=2em, itemsep=0.2em]
\item \textbf{Spatial calibration} maps patient-specific electrodes into atlas-grounded parcel tokens.
\item \textbf{Shared dynamics} operates only on those parcel tokens and predicts the phoneme sequence.
\end{enumerate}

The shared interface is
\begin{equation}
\bz \in \R^{B \times N_{\text{tok}} \times d \times T},
\end{equation}
with
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item $N_{\text{tok}} = 15$ fixed left-hemisphere Brainnetome parcels
\item $d = 64$ by default, with $d=128$ as the first width ablation
\item $T = 28$ temporal tokens per trial
\end{itemize}

Everything before this tensor is patient-specific observation geometry. Everything after it is shared sequence modeling.


%% ====================================================================
\section{Phase-1 Status}
%% ====================================================================

The Phase-1 design is \textbf{fixed atlas, supervised only, no learned calibration}. In particular:
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item use the real Brainnetome PM volume at \texttt{data/atlas/BNA\_PM\_4D.nii.gz}
\item trust the current ACPC$\to$MNI cache path from the Python port of Zac's \texttt{sub2AvgBrainClinical.m}
\item do not add learned gain, offset, rigid correction, parcel offsets, or parcel temperatures in Phase 1
\item do not use MFA in the training path
\item do not use data augmentation in the first benchmark run
\end{itemize}

One blocker remains outside the core architecture:
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item \textbf{\#34} end-to-end loading and timing audit
\end{itemize}

The spatial-base decision is now accepted: v14 pivots to a pure fsaverage surface pipeline. The remaining work is execution and verification of that pipeline, especially confirmation that the atlas-side bake uses real nonlinear sulcal/gyral surface alignment rather than an affine shortcut.

The architecture is intentionally small. The tokenizer extracts short local temporal features. The summarizer converts electrode-local features into one token per parcel per time step. The backbone models region-region and time-time interaction. The decoder reads out a fixed 3-slot phoneme sequence.

\section{Spatial Interface}
%% ====================================================================

\subsection{Coordinates and channel bridge}

The stable channel bridge ends at a physical electrode name. During the migration, the current trusted reference cache is
\begin{equation}
\texttt{data/mni\_coords/<pt>\_MNI152.csv}.
\end{equation}
The lookup key is the \emph{physical electrode name}, not a row index and not a TSV electrode name. Under the accepted fsaverage pivot, this same name-keyed bridge will terminate in a patient-side surface projection / fsaverage-vertex cache rather than a final MNI CSV lookup.

The channel bridge is:
\begin{equation}
\texttt{.fif channel} \rightarrow \texttt{amp channel} \rightarrow \texttt{layout map}
\rightarrow \texttt{physical electrode name} \rightarrow \texttt{cached MNI coordinate}.
\end{equation}

The mapping is layout-specific:
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item 128-strip patients use Map 4 from local \texttt{*\_channelMap.mat}
\item 256-grid patients use Map 3 from \texttt{*\_channelMapAll.mat}
\item S58 uses a cropped Map-3 variant that must be aligned back to the full Map 3
\item the stray \texttt{S39\_channelMap.mat} is not authoritative and must never be loaded
\end{itemize}

This bridge contract is frozen. The patient-by-patient verifier remains implementation work.

\subsection{Patient-side vs atlas-side surfaces}

The two sides of the fsaverage pipeline intentionally use different surfaces:
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item \textbf{Patient side}: project electrodes from each patient's \texttt{pial-outer-smoothed} surface through stock \texttt{sphere.reg}. This matches the physical fact that the electrodes sit on the dural envelope rather than on the cortical ribbon itself, and it preserves Zac's more consistent patient-to-template behavior.
\item \textbf{Atlas side}: sample the Brainnetome PM volume through the true cortical ribbon, from \texttt{white} to \texttt{pial}, using \texttt{mri\_vol2surf --projfrac-avg 0 1 0.1}. This is a cortical-column average, so it should be defined on the ribbon rather than on an envelope surface.
\end{itemize}

The role of \texttt{ICBM152\_fs} is also specific: it is not the atlas itself. It is the FreeSurfer reconstruction of the ICBM152 template, which provides white/pial surfaces in the same space as the BNA PM volume before the nonlinear \texttt{sphere.reg}-based transfer to fsaverage.

\subsection{Channel inclusion}

The input channel policy is:
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item use \textbf{all non-artifact channels}
\item do not silently filter to significant channels
\item remove artifact channels from the active channel axis; do not zero them in place
\end{itemize}

\subsection{Tier-1 parcels}

Phase 1 uses 15 fixed left-hemisphere Brainnetome parcels:
\begin{quote}
\texttt{A45c, A45r, IFS, A4hf, A44v, A9/46v, A12/47l, A4tl, A38l, A44d, A1/2/3tonIa, A1/2/3ulhf, IFJ, A6cvl, TE1.0/1.2}
\end{quote}

These were selected by the frozen rule
\begin{equation}
\texttt{argmax\_wins} \ge 10,
\end{equation}
on the current left-hemisphere Phase-1 cohort. Phase 1 uses
\begin{equation}
N_{\text{tok}} = 15, \qquad k_{\text{parcel}} = 1,
\end{equation}
so there is exactly one token per parcel.

\subsection{Support and validity}

Per-electrode parcel support is
\begin{equation}
\text{support}(e,p) = (G * PM_p)(x_e),
\end{equation}
where $PM_p$ is the Brainnetome probability map for parcel $p$, $x_e$ is the electrode coordinate, and $G$ is a Gaussian with $\sigma = 1.5$\,mm.

Under the accepted fsaverage path, the operational lookup is no longer a 3D volumetric query at runtime. The atlas is baked onto the fsaverage pial surface once, and support is read on the 2D surface after patient-side projection to the same surface. The old nearest-neighbor 8\,mm dilation bridge belongs to the retired \texttt{cvs\_avg35} path and is not part of the target v14 spatial design.

An electrode is valid iff:
\begin{enumerate}[leftmargin=2em, itemsep=0.2em]
\item its parcel argmax lands in Tier-1, and
\item its maximum parcel support is \(> 0\).
\end{enumerate}

There is no extra support threshold in the baseline rule.

\subsection{Token mask and token support}

Two parcel-level metadata signals are carried through the model:
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item \texttt{token\_mask[p]}: hard parcel presence
\item \texttt{token\_support[p]}: graded parcel support
\end{itemize}

They are intentionally different:
\begin{equation}
\texttt{token\_mask}[p] = 1
\quad \text{iff parcel $p$ has at least one electrode whose argmax parcel is $p$},
\end{equation}
while
\begin{equation}
\texttt{token\_support}[p] = \sum_e \text{support}(e,p)/100.
\end{equation}

So \texttt{token\_mask} is argmax-based existence, while \texttt{token\_support} is full-support parcel strength.

\subsection{Parcel-frame chart}

Each parcel uses a deterministic local tangent chart defined directly on the baked fsaverage pial surface. This is a 2D chart, not a 3D volumetric frame.

The frame is built from the raw baked parcel weights before geodesic smoothing. For parcel $p$:
\begin{enumerate}[leftmargin=2em, itemsep=0.2em]
\item compute the parcel centroid on fsaverage using the raw parcel weights and snap it to the nearest in-parcel vertex; this snapped vertex is the origin
\item define the local outward axis $z$ as the normalized weighted mean of in-parcel pial normals, flipped if needed to agree with the origin-vertex pial normal
\item if that weighted mean is numerically too small, fall back to the origin-vertex pial normal directly
\item define the first tangent axis $u$ by projecting the global anterior direction into the plane orthogonal to $z$
\item if that projection is numerically too small, fall back in fixed order to projected superior, then projected left-right
\item define the second tangent axis by
\begin{equation}
v = \frac{z \times u}{\|z \times u\|},
\end{equation}
which gives a right-handed basis with no extra sign choice
\end{enumerate}

An electrode projected to fsaverage pial is then encoded by its signed local offsets in this chart:
\begin{equation}
\Delta x = x_e - x_{0,p},
\qquad
u_e = \Delta x^\top u_p,
\qquad
v_e = \Delta x^\top v_p.
\end{equation}

The point encoder sees normalized coordinates
\begin{equation}
\left[\frac{u_e}{\sigma_u}, \frac{v_e}{\sigma_v}\right],
\end{equation}
where $\sigma_u$ and $\sigma_v$ are parcel-weighted standard deviations of in-parcel vertices along the same axes. The parcel token also receives \(\log \sigma_u\) and \(\log \sigma_v\) as side metadata.

This chart is intentionally simple. It keeps coordinate semantics consistent across parcels:
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item $u$ is as anterior-pointing as the local tangent plane allows
\item $v$ is the corresponding right-handed tangent direction
\item $z$ is the outward pial normal, used only to define the chart
\end{itemize}

The frame cache should not be trusted from formulas alone. The builder should emit fsaverage visualizations for every Tier-1 parcel showing the parcel support map, the origin, and the local \(u,v,z\) axes. All 15 parcels should be inspected once before the cache is used in training, and the build should fail on obviously flipped, degenerate, or anatomically nonsensical frames.


%% ====================================================================
\section{Temporal Tokenizer}
%% ====================================================================

The temporal front-end is deliberately simple:
\begin{equation}
\bx \in \R^{B \times N_{\text{ch}} \times 301}
\;\rightarrow\;
\bh \in \R^{B \times N_{\text{ch}} \times d \times 28}.
\end{equation}

For each electrode independently, apply a shared Conv1d patch projection with:
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item input rate: 200\,Hz
\item kernel: 150\,ms = 30 samples
\item stride: 50\,ms = 10 samples
\item output rate: 20\,Hz
\end{itemize}

This is a short-range feature extractor, not a separate temporal backbone. The token semantics are overlapping temporal patches, not continuous framewise states.


%% ====================================================================
\section{Within-Parcel Summarizer}
%% ====================================================================

For each parcel $p$ and time step $t$, the summarizer receives the set of electrodes whose argmax parcel is $p$. There is no cross-parcel duplication.

Each electrode item carries:
\begin{equation}
\bigl[\text{temporal feature},\; \text{parcel-frame coordinate},\; \log\sigma,\; \text{scalar support},\; \text{parcel embedding}\bigr].
\end{equation}

The summarizer is shared across parcels and across patients. Parcel identity enters as an input feature, not as a separate module per parcel.

The baseline summarizer is one-latent Perceiver-style cross-attention:
\begin{equation}
\text{item}_e \rightarrow \bh_e,
\qquad
\bs_{p,t} = \text{CrossAttn}(q_p, \{\bh_e\}_{e \in p,t}),
\end{equation}
with standard settings:
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item one latent query per parcel-time slice
\item pre-norm
\item head dimension 32
\item dropout 0.1
\item no latent self-attention stack
\end{itemize}

Support enters in two ways:
\begin{enumerate}[leftmargin=2em, itemsep=0.2em]
\item as a scalar input feature
\item as an additive attention-logit bias
\end{enumerate}

The attention form is
\begin{equation}
a_e = \frac{q^\top k_e}{\sqrt{d_h}} + \alpha \log(\text{support}(e,p) + \epsilon),
\qquad
w_e = \operatorname{softmax}_e(a_e),
\qquad
\bs_{p,t} = \sum_e w_e v_e,
\end{equation}
with learnable scalar $\alpha$.


%% ====================================================================
\section{Shared Backbone}
%% ====================================================================

After summarization, the model operates on
\begin{equation}
\bz \in \R^{B \times N_{\text{tok}} \times d \times T},
\qquad N_{\text{tok}} = 15, \; T = 28.
\end{equation}

The backbone uses \textbf{factored spatial-then-temporal attention}. Each block does:
\begin{enumerate}[leftmargin=2em, itemsep=0.2em]
\item spatial attention over the 15 parcel tokens at fixed time
\item temporal attention over the 28 time steps within each parcel token
\end{enumerate}

The baseline uses
\begin{equation}
B = 2
\end{equation}
spatial-temporal block pairs.

Each block is a standard Transformer block:
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item pre-norm
\item residual around attention
\item residual around FFN
\item FFN width \(4d\)
\item GELU
\item dropout 0.1
\item head dimension 32
\end{itemize}

Temporal attention uses RoPE. Spatial attention uses no positional encoding.

\subsection{SC/FC prior}

Spatial attention receives a soft prior from structural and functional connectivity:
\begin{equation}
\text{score}(i,j)
=
\frac{q_i^\top k_j}{\sqrt{d_h}}
+
\gamma_{\text{sc}} B_{\text{sc}}(i,j)
+
\gamma_{\text{fc}} B_{\text{fc}}(i,j),
\end{equation}
where
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item $B_{\text{sc}}$ and $B_{\text{fc}}$ are normalized parcel-by-parcel bias matrices
\item $\gamma_{\text{sc}}$ and $\gamma_{\text{fc}}$ are learned scalar gains
\item the prior is additive only, so it remains a soft bias
\end{itemize}

\subsection{Masking}

Absent parcels are masked in spatial attention. Masked rows are then zeroed after each block. The zeros are storage-only; the mask carries the semantics.

The full \((N_{\text{tok}}, d, T)\) tensor is handed to the decoder. There is no early pooling over time or parcel tokens.


%% ====================================================================
\section{Decoder and Supervision}
%% ====================================================================

The target is a fixed 3-slot phoneme sequence over the 9 canonical ARPABET classes:
\begin{quote}
\texttt{AA, AE, B, G, IY, K, P, UW, V}
\end{quote}
with alphabetical index order
\begin{equation}
\texttt{AA}=0,\;
\texttt{AE}=1,\;
\texttt{B}=2,\;
\texttt{G}=3,\;
\texttt{IY}=4,\;
\texttt{K}=5,\;
\texttt{P}=6,\;
\texttt{UW}=7,\;
\texttt{V}=8.
\end{equation}

The decoder is one small autoregressive block:
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item one learned base query plus one slot embedding per position
\item previous-token embedding injected into the query stream
\item one causal self-attention layer across the 3 slots
\item one cross-attention layer over the flattened parcel-time memory
\item one shared linear vocab head
\end{itemize}

If \(M \in \R^{(N_{\text{tok}}T) \times d}\) is the flattened backbone memory, then slot $k$ computes
\begin{equation}
q'_k = q_k + \operatorname{emb}(y_{k-1}),
\qquad
u_k = \operatorname{CausalSelfAttn}(q'_k),
\qquad
o_k = \operatorname{CrossAttn}(u_k, M),
\qquad
\hat{y}_k = W o_k.
\end{equation}

Training uses teacher forcing. Evaluation does \textbf{not} use teacher forcing.

\subsection{Loss and decode}

The baseline supervised loss is plain slot-wise cross-entropy:
\begin{equation}
\mathcal{L}
=
\frac{1}{3}\sum_{k=1}^{3} \operatorname{CE}(\hat{y}_k, y_k).
\end{equation}

There is no label smoothing, focal loss, mixup, or auxiliary token head in the first benchmark run.

Evaluation uses exhaustive decoding over all
\begin{equation}
9^3 = 729
\end{equation}
possible sequences. Greedy decoding is allowed as a comparison path only. The reported metric is slot-averaged phoneme error rate (PER).


%% ====================================================================
\section{Training and Evaluation Defaults}
%% ====================================================================

These are not architecture innovations. They are frozen first-run defaults chosen to prevent protocol drift.

\subsection{Evaluation}

\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item grouped-by-token cross-validation
\item 5 outer folds
\item 3 seeds: 42, 137, 256
\item 20\% grouped validation split within each training fold
\item same train/val partition reused across seeds within fold
\item report per-patient PER mean $\pm$ std across seeds, then population mean
\end{itemize}

\subsection{Training}

\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item optimizer: AdamW
\item base learning rate: \(10^{-3}\)
\item weight decay: \(10^{-4}\)
\item scheduler: cosine decay
\item warmup: 20 epochs
\item gradient clipping: 1.0
\item mixed precision on by default on DCC unless unstable
\item early stopping on validation PER
\end{itemize}

\subsection{Batching}

\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item grouped-by-patient batches
\item baseline run is per-patient first
\item \texttt{trials\_per\_batch = 8}
\item effective batch target 32 via gradient accumulation if needed
\item max epochs 300
\item patience 10 validation checks
\item validation every 5 epochs
\end{itemize}


%% ====================================================================
\section{What Is Deferred}
%% ====================================================================

The following are explicitly not part of the Phase-1 base architecture:
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item learned per-patient calibration
\item SSL pretraining
\item sEEG
\item right-hemisphere integration
\item external datasets
\item broad recipe ablations
\end{itemize}

For future external datasets with uncertain MNI quality, one reasonable fallback is:
\begin{enumerate}[leftmargin=2em, itemsep=0.2em]
\item freeze the shared neural network weights
\item fit a per-patient rigid-body coordinate adapter only
\item restrict that adapter to rotation plus translation, not free affine warping
\end{enumerate}

That should be treated as an explicit external-dataset adaptation step, not as part of the base Phase-1 contract.

\section{Open Items}
%% ====================================================================

The architecture core is frozen, but one important item remains outside the model itself:
\begin{itemize}[leftmargin=2em, itemsep=0.2em]
\item \textbf{\#34} the loading and timing audit still gates the loader
\end{itemize}

So the correct reading of this document is:
\begin{quote}
The Phase-1 \emph{model} is defined. The remaining uncertainty is in data-path verification, not in the shared neural architecture.
\end{quote}
